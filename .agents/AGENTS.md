# Project Rules — Playwright Automation Suite

## Project Structure
- **Config**: `playwright.config.js` (CommonJS)
- **Tests**: `tests/<project-name>/` — organized by project (anvesha, saucedemo, api, practice)
- **Utilities**: `utils/` — shared helpers (login, excel reader, test data generator)
- **Test Data**: `test-data/<project-name>/` — JSON fixtures per project
- **Test Plans**: `specs/` — Markdown test plans generated by the Planner agent

## Coding Conventions
- Use **CommonJS** (`require`/`module.exports`), NOT ES modules
- Import from `@playwright/test`: `const { test, expect } = require('@playwright/test');`
- Use descriptive `test.describe()` blocks with section comments
- Prefer semantic locators: `#id`, `[data-test="..."]`, `.class`, then XPath as last resort
- Add step-by-step comments explaining each action
- Use `test.beforeEach` for common navigation/setup
- Load test data from JSON files in `test-data/`

## Naming Conventions
- Test files: `NN-feature-name.spec.js` (zero-padded number prefix, kebab-case)
- Test data: `test-data/<project>/filename.json`
- Utility helpers: `utils/feature-helper.js`

## Test Patterns
- Each `test.describe` block groups related scenarios
- Assertions use `expect()` with Playwright matchers (`toHaveURL`, `toBeVisible`, `toContainText`, etc.)
- Error scenarios are always tested alongside happy paths
- Navigation to base URL uses `page.goto('/')` (baseURL from project config)

## Playwright Config
- Projects: `anvesha` (localhost:5000), `saucedemo` (saucedemo.com), `api`, `practice`
- Browser: Desktop Chrome
- Timeouts: 60s test, 15s expect/action
- Screenshots on failure, trace on first retry
